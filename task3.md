# ДЗ-3. Часть 1. Практика

В этом ДЗ в проект будет добавлена возможность хранения результатов работы приложения. Считаем, что выполнение операции занимает много времени (т.е. выполнение операции - дорогостоящее), а, значит, нужно избегать повторного выполнения операций, которые уже были выполнены. Поэтому приложение должно сохранять числа, операцию и результат выполнения операции.

## Задание

Добавить в приложение возможность хранения результатов работы в следующих форматах.

Медленный доступ, долговременное хранение. Для персистентного хранения используй БД.

В БД должна храниться следующая информация:
- числа, над которыми выполняется операция
- сама операция
- результат
- статус выполнения операции: 0 - успех, номер ошибки - выполнение операции закончилось с ошибкой (например, деление на 0)

В качестве БД необходимо использовать PostgreSQL. Выбор схемы БД остается на твое усмотрение. Для работы с Postgres из C++ кода тебе нужно написать собственную минимальную оболочку для библиотеки libpq. Использовать библиотеку libpqxx запрещено!

Быстрый доступ, кратковременное хранение - кеш. Размер кеша не ограничен. Для кеша можешь использовать std::unordered_map. В качестве ключа std::unordered_map можешь использовать строку, в которую записана выполняемая операция "1+2". Обращая твоё внимание, что "1+2" и "2+1" - это идентичные операции.

Считаем, что размер данных, которые хранятся в БД достаточно мал (несколько Мб). При старте приложение должно считывать историю операций из БД в кеш ("прогревать" кеш). При поступлении новых данных приложение проверяет наличие данных в кеше, если данные есть - забирает результат из кеша. Если данных нет, выполняет расчет и записывает результат в кеш и в БД.

Напоминаю, что все классы твоей оболочки должны поддерживать идиому RAII.

Для того, чтобы быть уверенным, что ты корректно освобождаешь ресурсы, используй Valgrind.

Самое время подумать о производительности твоего приложения: используй Perf и попытайся найти узкие места в работе твоего приложения.
