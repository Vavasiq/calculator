# ДЗ-4. Практика

В текущий момент твой проект представляет собой утилиту командной строки: утилита получает задание при запуске, выполняет расчет и завершает свою работу. Самое время сделать из твоего проекта настоящий Linux сервис!

Что должно получиться в итоге: твой сервис запускается и работает до тех пор (т.е. принимает задания на расчет и возвращает результат), пока он не получит сигнал на завершение работы.

Для этого тебе предстоит реализовать следующий функционал.

Сделать из твоего проекта systemd сервис. Сервис должен выполнять следующие команды.

Запуск сервиса:

```bash
sudo systemctl start имя_сервиса
```

Перезапуск сервиса:

```bash
sudo systemctl restart имя_сервиса
```

Остановка сервиса:

```bash
sudo systemctl stop имя_сервиса
```

Обращаю твоё внимание, что в твоем проекте должно быть минимум 2 потока: первый поток получает и обрабатывает сигналы ОС, второй поток - занимается получением данных и их обработкой.

Тестировать получение и обработку сигналов не нужно.

Обязательно выполни проверку своего проекта ThreadSanitizer на наличие гонок данных и deadlock. Эту проверку нужно выполнить для итоговой версии сервиса, т.е. после реализации всех пунктов ДЗ.

В сервис необходимо добавить поддержку клиент-серверной архитектуры: сервис (сервер) получает задание на расчет от клиента, после выполненного расчета сервер отправляет клиенту результат расчета.

В базовой части ДЗ тестировать одновременное подключение нескольких клиентов не нужно — считаем, что к серверу подключается только один клиент за раз.

Для сетевого взаимодействия используй Boost.Asio.

Тесты необходимо доработать с учетом того, что твой сервис теперь принимает задания по сети: тебе необходимо написать тестовый клиент к твоему сервису. Клиент отправляет данные твоему сервису, в ответ получает результат расчета. Проверять нужно именно полученный результат расчета. Постарайся избегать использования sleep_for и других видов sleep, вместо них используй busy циклы с ограничением работы по времени.

Создай deb-пакет для своего сервиса с помощью CPack. В deb-пакет добавь бинарник и конфигурационные файлы.

Это ДЗ ты будешь полностью выполнять с помощью ИИ. Твоя цель: научится декомпозировать задание и писать для ИИ короткие запросы для последовательной реализации требуемого функционала. При работе с ИИ ты должен помнить о следующих особенностях:

- ИИ плохо работают с объемными задачами. Объемную задачу нужно разбить на несколько маленьких подзадач и последовательно попросить ИИ реализовать каждую из них.
- ИИ лучше справляется с задачами, если у него есть документ с подробными требованиями, как нужно выполнять задачу. Этот документ может разработать сам ИИ под твоим контролем. Только после того, как документ будет разработан, можно давать ИИ команду писать код.
- ИИ может собирать за тебя проект и анализировать ошибки сборки проекта. ИИ может запускать тесты и анализировать ошибки выполнения тестов. Учти, что все эти операции требуют токенов. Поэтому иногда лучше выполнять их руками.

ДЗ-4 можно разбить на следующие задачи.

- Задача 1. Добавить обработку системных сигналов. Приложение должно завершать свою работу после того, как оно получит сигнал SIGTERM.
- Задача 2. Создать файлы конфигурации systemd. Приложение должно управляться с помощью команд systemd, команды приведены в тексте ДЗ.
- Задача 3. Добавить получение данных по сети с помощью boost.asio, написать тесты. Требования приведены в тексте ДЗ.
- Задача 4. Добавить сборку deb-пакета.

С помощью ИИ разработай 4 документа с подробным планом изменений, которые нужно внести в проект — по одному документу на каждую из 4 задач. После завершения работы над каждым из документов попроси ИИ написать код.
