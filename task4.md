# ДЗ-4. Linux-сервис

Сейчас проект — утилита командной строки: при запуске получает задание, выполняет расчёт и завершает работу. Нужно сделать из проекта настоящий Linux-сервис.

**Итоговый результат:** сервис запускается и работает (принимает задания на расчёт и возвращает результат), пока не получит сигнал на завершение работы.

## Требования

### 1. systemd-сервис

Проект должен стать systemd-сервисом и поддерживать команды:

```bash
sudo systemctl start имя_сервиса     # запуск
sudo systemctl restart имя_сервиса   # перезапуск
sudo systemctl stop имя_сервиса      # остановка
```

### 2. Потоки

В проекте должно быть **минимум 2 потока**:
- первый поток получает и обрабатывает сигналы ОС;
- второй поток получает данные и обрабатывает их.

Тестировать получение и обработку сигналов не нужно.

### 3. ThreadSanitizer

Проект обязательно проверяется ThreadSanitizer на гонки данных и deadlock. Проверка выполняется для **итоговой** версии сервиса, т.е. после реализации всех пунктов ДЗ.

### 4. Клиент-серверная архитектура

- Сервис (сервер) получает задание на расчёт от клиента, после расчёта отправляет клиенту результат.
- В базовой части одновременное подключение нескольких клиентов тестировать не нужно: к серверу подключается только один клиент за раз.
- Для сетевого взаимодействия используется **Boost.Asio**.

### 5. Тесты

Тесты дорабатываются с учётом того, что сервис принимает задания по сети:
- нужно написать тестовый клиент к сервису;
- клиент отправляет данные сервису и получает в ответ результат расчёта;
- проверяется именно полученный результат расчёта;
- избегать `sleep_for` и других видов sleep — вместо них использовать busy-циклы с ограничением по времени.

### 6. deb-пакет

Создать deb-пакет сервиса с помощью **CPack**. В пакет входят бинарник и конфигурационные файлы.

## Разбиение на задачи

| № | Задача | Критерий готовности |
|---|--------|---------------------|
| 1 | Обработка системных сигналов | Приложение завершает работу после получения `SIGTERM` |
| 2 | Конфигурация systemd | Приложение управляется командами `systemctl start/restart/stop` |
| 3 | Получение данных по сети через Boost.Asio + тесты | Выполнены требования разделов 4 и 5 |
| 4 | Сборка deb-пакета | Пакет собирается CPack и содержит бинарник и конфиги |

## Порядок работы

ДЗ полностью выполняется с помощью ИИ. Цель — научиться декомпозировать задачу и писать ИИ короткие последовательные запросы.

- Объёмную задачу разбивать на маленькие подзадачи и реализовывать их последовательно.
- Для каждой из 4 задач сначала разработать с ИИ документ с подробным планом изменений (под своим контролем) и только после этого просить писать код.
- ИИ может собирать проект, запускать тесты и анализировать ошибки, но это тратит токены — иногда лучше делать это вручную.
